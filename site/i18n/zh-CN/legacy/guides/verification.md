本页单独记录验证范围。[项目状态](/orbitjob/docs/status/)概述实现；[已知问题](/orbitjob/docs/known-issues/)列出尚未解决的限制。[CONTRIBUTING](https://github.com/s3loy/orbitjob/blob/main/CONTRIBUTING.md#testing) 定义必需质量检查。

<a id="evidence-levels"></a>
## 证据层级

| 层级 | 结果能够证明的内容 |
|---|---|
| 单元与竞态测试 | 给定测试边界内的领域、应用、适配器和并发行为 |
| PostgreSQL 集成 | 记录版本数据库中的实际迁移、事务、RLS、角色、授权和仓储行为 |
| Helm 与 schema 检查 | 迁移副本一致性、渲染配置、RBAC，以及生成的 API/CRD 契约 |
| 已安装场景 | 指定镜像、Kubernetes 拓扑和受控故障用例中观察到的行为 |
| 浏览器 fixture | 指定 fixture 或模拟 HTTP 配置下的 Console 导航与交互 |
| 文档检查 | 源码生成、翻译、代码示例、链接、锚点和浏览器导航 |

通过结果仅适用于其源码输入和测试环境。安装就绪不能单独证明业务恢复。受控领导权丢失测试不能证明任意网络分区韧性或生产高可用。

<a id="backend-design-checks"></a>
## 后端设计检查

| 边界 | 验证方法 |
|---|---|
| 管理与账本归属 | 检查 Admin/Runtime 数据库授权、事务归属，以及真实角色拒绝用例 |
| 授权与租户隔离 | 测试显式 Deny、委派边界、派生父资源作用域、RLS 和跨租户引用 |
| 来源准入 | 将不同请求和精确重放与来源生命周期变更并发执行；验证待准入状态和固定执行载荷 |
| 执行恢复 | 移除所属 Job 证据，验证原始身份和非终态 Unknown 行为，并恢复保留的终态事实 |
| 领导权 | 观察实际 Lease 续约、失去任期后的取消与排空，以及恢复权限后的成功调度 |
| 取消 | 确认所属执行已终止；证据缺失时保留不确定状态；保留无关 Kubernetes 对象 |
| 结果投影 | 重放终态事实而不重复增加 SLI 计数；历史清理保留待完成投影 |
| 执行归档 | 验证保留输出、归属检查、独立读取和删除权限、容量限制及重启持久性 |
| 安装与迁移 | 验证全新安装、重复升级、迁移失败处理，以及卸载重装后的数据保留 |

重建 schema 的测试使用独立 PostgreSQL 实例。安装和故障场景使用专用 kind 集群与 kubeconfig。两套测试均不得把操作者正在使用的数据库作为一次性 fixture。

<a id="personal-accounts"></a>
### 个人账户

账户服务与 HTTP 使用流程在一次性 PostgreSQL 实例上，以 `orbitjob_admin` 角色验证。HTTP 流程覆盖设置、会话恢复、精确 Origin 和 CSRF 拒绝、近期密码确认、带创建者成员资格的工作区创建、邀请、跨工作区拒绝、密码重置与修改、账户和成员停用、退出，以及旧 Bearer 认证。其中 Function 调用使用 Kubernetes dynamic fake，不证明已安装工作负载执行。

定向数据库用例还验证单次设置与邀请竞态、会话过期和撤销、最后一位活动安装管理员保护、数据库角色权限、策略 Deny 与边界执行，以及全局密码重置与工作区管理的隔离。最终审阅回归验证重新启用成员时保留授权、继承或更窄的成员边界，以及恢复后旧重置链接与会话失效。

另一个浏览器使用已编译 Console 和真实账户 HTTP、PostgreSQL 服务，完成首位管理员设置、错误密码拒绝、重新加载后的会话恢复、七天记住登录 cookie 创建和退出。本地测试显式启用不安全回环模式；生产 cookie 属性由 HTTP 测试检查。此浏览器检查不证明生产 HTTPS 部署或已安装集群升级。

完整 PostgreSQL 检查在 `internal/core/store/postgres` 中运行 `TestDeletedSnapshotStepsRemainSubjectToExplicitExecutionPause` 时超过十分钟包截止时间。此前迁移、bootstrap、Admin HTTP 和 Admin store 包通过。剩余负载测试包为降低工作站负载而停止。随后在独立 PostgreSQL 实例上的运行通过全部七个包，见后文可靠性与账户维护检查。已安装账户系统部署仍待完成。

### 安装 origin 与当前源码本地升级

2026-11-15，现有单节点 Kubernetes v1.37.0 `orbitjob-dev` 安装从 Helm 初始化的迁移账本 0001–0014 升级至 0001–0026。安装了七个当前源码 Linux arm64 组件镜像、当前 CRD 与匹配 RBAC。迁移前完成数据库与归档协调备份。原 bootstrap 凭据、资源 UID 和全部历史迁移校验和均保留。

真实 API 检查完成了定义验证、保存、准入查询、手动触发和成功的 Kubernetes 执行。保留的容器输出与执行归档均返回预期输出。检查使用真实 Admin API、Operator、Admission 服务、PostgreSQL 和日志组件。

Service/Ingress schema、渲染路由和安装说明通过定向 Go 测试及 `make helm-check`。Console 生成、TypeScript、lint、220 个单元测试、生产构建与格式检查通过。六个浏览器回归用例使用非 localhost 的 HTTP origin，原生 `randomUUID` 和 Clipboard API 不可用；API 响应使用 fixture。

完整浏览器 fixture 套件执行 304 个用例：276 个通过，28 个失败。失败包括定义 fixture 契约不匹配、旧导航选择器、不唯一的 alert 定位器和超时。部分失败没有修改前基线；此结果不构成完整 Console 验收。

已编译的安装版 Console 还通过非 localhost 的 HTTP 浏览器 origin 连接真实升级后 API。传输请求转发到本地 Admin 服务，未替换 API 响应。一次手动触发以 `Succeeded` 完成，保留输出可见，重新加载后再次认证返回原 Run URL。原生 `randomUUID` 和 Clipboard API 不存在；1440 px 下页面未报告运行时错误或水平溢出。

独立回环反向代理探针在 HTTP 主机名、HTTPS 主机名，以及带非默认端口的 HTTPS IP 地址上通过 21 项检查。它保留同源认证，并拒绝公开 metrics 和 health 路径。TLS 检查按显式本地信任根验证探针证书。该结果不验证外部 Ingress 控制器、公共 DNS、证书签发或续期、全新机器安装或生产部署。

## 可靠性与账户维护检查（2026-11-15）

独立 PostgreSQL 17 实例通过当前可靠性与个人账户候选版本的全部七个集成包。测试从迁移 0001–0027 重建隔离 schema，覆盖迁移与 schema 权限归属、Admin/Runtime 角色限制、租户隔离、来源准入和暂停、SLI 记录与清理并发、执行隔离清单，以及恢复 canary 验证。未改写早期迁移字节或当前安装迁移账本。

账户回归覆盖已认证邀请绑定、仅安装管理员可用的全局密码重置、恢复使旧重置能力令牌与会话失效，以及仅对实际撤销的会话产生审计。成员重新启用会检查完整已保存授权，不静默修改。受边界约束的管理员不能恢复缺失边界或更宽边界。独立数据库会话验证事务锁；注入审计失败验证成员状态和审计历史一起回滚。

完整 Console fixture 使用模拟 HTTP 响应。该轮运行期间账户入口和样式有变更；之后追加的 73 项账户与布局复验检查了最后输入，且复验期间这些输入保持不变。浏览器结果不构成已安装 Console 套件通过，也不证明当前集群已完成账户升级。受影响指南翻译和标题搜索修复后，两种语言的文档均通过生成与浏览器检查。

之后的独立审查复现了同用户会话竞态：安装新会话绑定后，旧账户请求仍可能返回 401，清除有效会话的界面状态。账户传输层现已在 CSRF 绑定变化时更新请求生命周期，丢弃旧成功与失败响应；绑定未变的刷新会保留在途请求。定向传输套件通过 11 项，浏览器回归通过三项，审查者另独立通过四项生命周期与正文解析检查。

此次审查期间，其他 UI 工作仍在并行变更。观察到的两项 TypeScript 错误和一项 readiness 文案断言失败随后均已修复。最终前端检查通过生成契约检查、类型检查、lint、全部 235 项单元测试和生产构建。之前完整浏览器 fixture 结果适用于各自记录的输入；最终并行 UI 改动完成后，未重新运行该完整套件。本次账户定向回归不能证明完整前端或已安装环境验收通过。

一次性单节点 Kubernetes v1.37.0 kind 集群通过原生 `kindest/kindnetd:v20260820-69b56db7` 的 16 项真实网络检查。检查使用 chart 渲染策略，在拒绝前后验证目标健康，覆盖 DNS、默认入站和出站拒绝、一个允许 CIDR/端口，以及第二端口拒绝。不应用策略的负对照产生预期的出站拒绝检查失败。两次运行均移除探针资源，不需要额外策略提供程序。

同一一次性节点测试了专用 256-MiB ext4 采集器文件系统：物理空间耗尽返回 `ENOSPC`，保留状态在节点重启后仍存在，镜像缺失会通过必需挂载依赖阻止 kubelet 启动。恢复镜像后，挂载和保留的哨兵文件恢复。这些检查使用本次演练拥有的路径，不使用当前采集器目录。实验后已删除临时集群。

[当前集群维护流程](/orbitjob/docs/local-maintenance/)仍是方案，未启用其网络与配额标志，也未向该集群部署候选版本。最终检查时，当前节点为 Ready 且无压力条件；但并发验证期间多个组件曾重启，事件记录了探针超时，部分退出码为 137。记录不能证明 OOM 原因。宿主空闲空间仍低于 40-GiB 安装前置要求。已安装账户切换、完整故障场景和 standard/long 负载资格验证仍待完成。

<a id="recovery-and-upgrade-scope"></a>
## 恢复与升级范围

取消验收要求实际容器退出、证据保留、PostgreSQL 持久化、finalizer 解除和原 Job 删除。控制器确认必须先于完整清单采集。测试必须区分缓慢但已确认的停止与不可逆证据缺口：解除无关删除保留可使前者完成，终止事实缺失时仍保持 unknown。

原生验收套件覆盖正常成功与失败、平台和 Kubernetes 重试、已配置截止时间、取消、Operator 和数据库故障、控制器延迟，以及中断的 finalizer 解除。未调度的终态 Pod 缺少可信容器退出信息时，必须保留证据和 unknown 状态。仅准备故障运行器不构成通过结果。

2026-10-29 备份恢复演练比较了 22 张数据库表、14 个序列和 807 个归档文件，并通过恢复后及原 API 检查保留记录。在恢复首次清理等待失败后，演练完成。此结果适用于前一个已安装候选版本，不证明后续取消协议、在其他服务端重建共享数据库角色或生产灾难恢复。

升级验收必须从真实已发布 v0.2.1 镜像及其原迁移输入渠道开始。必须验证已有凭据与历史、迁移切换、重复升级，以及恢复升级前备份。全新安装或同一候选版本的第二次升级不能替代此兼容性检查。

<a id="qualification-boundaries"></a>
## 资格验证边界

当前检查不证明生产发布、已发布镜像可用性、量化吞吐、长期容错、任意网络分区恢复或工作负载恰好一次效果。Standard/long 负载资格验证与独立业务恢复探针仍需单独完成。兼容性测试在支持升级或回滚结论前，必须标明真实新旧镜像和迁移输入渠道。
