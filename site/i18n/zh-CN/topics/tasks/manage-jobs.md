# 创建和更新作业

作业定义为手动和计划运行提供容器配置。编写过程保存定义；Operator 异步发布其
可执行修订版本。现有运行保留其固定修订版本。

## 开始前

使用具有 `job:Apply`、`job:Get` 和 `job:List` 的有效工作区成员资格。
在线编写要求凭据不受资源组限制，并具有映射到工作区的执行命名空间。
默认 Administrator 邀请不提供 `job:Apply`；应向工作区管理员申请显式授权。
安装实例管理员配置命名空间映射和 Kubernetes RBAC。

使用已批准的运行时预设或自定义容器镜像。审核其代码、参数、资源需求、允许的
网络目标和重复执行行为。创建定义不授予镜像仓库访问、Secret 访问或任意
Kubernetes 资源访问权限。

## 创建定义

1. 打开 **Jobs → Create a job**。使用默认 Shell 运行时、选择其他运行时、
   选择任务模板或复用 Job。设置唯一名称和已授权命名空间。
2. 选择 **Manual only** 或 **Scheduled and manual**。作业 cron 调度使用
   五个字段和 UTC。调度为空时不会自动触发作业。
3. 检查超时和运行策略默认值。任务需要覆盖时，打开资源和重试设置。
   保存前阅读执行预览。
4. 选择 **Review and save**，再选择 **Check against cluster**。检查准确的
   准入后配置，包括 Kubernetes 准入所做的更改。
5. 选择 **Save definition** 并确认。保留回执，等待 **Saved version is ready**
   后再请求运行。

集群检查使用预演请求。持久化要求提供该已检查配置的摘要和稳定请求身份。
保存成功不代表 Operator 已就绪或工作负载已经执行。完整示例请参阅
[第一个作业教程](../tutorials/first-job.md#create-a-job-as-an-author)。

## 从任务模板开始

选择 **Choose a task template**，准备消息、HTTP 状态检查或 JSON 任务。
每个模板提供可编辑默认值，并说明输入要求。输入改变时，执行预览同步更新，
显示将复制到 Job 中的镜像、程序、脚本及独立参数值。输入无效时阻止应用，
并在受影响字段旁显示错误。

**Use this template** 准备普通 Job 草稿，不会连接 HTTP 目标、执行代码、
保存定义或启动运行。替换已有草稿需要确认，并保留其目标命名空间。模板从手动
模式开始，采用一个 Attempt 且不进行 Pod 重试。保存前检查生成的名称、执行内容
和策略；生成的代码仍可编辑。

消息模板将文本输出到日志。HTTP 模板发出一次 GET 请求，不跟随重定向，将响应
状态与预期状态比较，并在不匹配或网络错误时失败。它要求执行容器能够访问目标。
JSON 模板格式化内联 JSON，或选择一个顶层字段，将其 JSON 表示输出到日志。
这些模板不创建持久化文件。输入值成为 Job 定义的一部分，因此不要在其中输入
凭据或机密数据。

## 选择运行时与执行内容

新草稿从手动 Shell 示例和 `busybox:1.37.0` 开始。**Runtime** 还提供使用
`python:3.14-slim` 的 Python 和使用 `node:24-bookworm-slim` 的 Node.js，
均带有可编辑 Hello 代码。切换未修改的示例无需确认；替换已修改代码或自定义
镜像则需要确认。**Custom image** 保留当前配置。额外依赖必须存在于镜像中；
选择运行时不会安装软件包。镜像仍需通过现有集群检查和镜像策略。

**Command** 在一个字段中接受程序及其参数。引号将内容组成一个参数，包括空值；
单引号外的反斜杠转义下一个字符。该字段不执行 shell 语法，也不展开变量。
脚本模式将多行代码传给对应解释器。引号未闭合和空脚本会阻止审核和保存。
包含额外 command 条目的导入定义，在 **Exact command and arguments** 中保留
原数组。Kubernetes 变量展开和镜像启动配置仍然适用。

## 生成调度

选择 **Scheduled and manual** 后，选择 **Generate schedule**，配置常用的
分钟间隔、每小时、每日或每周设置。只有 **Use this schedule** 会写入生成的
五字段 cron 表达式。取消会保留现有表达式，包括生成器无法表示的自定义模式。
作业调度使用 UTC：`0 2 * * *` 表示每天 UTC 02:00。生成器不会计算未来触发时间，
也不会自行启用自动执行。Workflow 编写使用同一生成器及其配置的时区。

## 更新定义

打开作业的 **Definition** 视图并编辑当前定义。保存前再次审核并检查更改。
写入比较原始 UID 和 resourceVersion；并发更改会产生冲突。重新加载已改变的
定义，检查差异，再重新应用预期更改。不要通过提交同名创建请求绕过冲突。

更改定义不会修改现有 Run 固定的镜像、命令、资源或重试预算。如果投影 generation
比保存回执更新，应先检查较新定义，再触发执行。

## 配置执行行为

`maxAttempts` 包括首次平台 Attempt。Kubernetes `backoffLimit` 控制每个
Attempt 内的 Pod 替换。任一设置启用重复执行时，版本 1 都要求 `retrySafe`。
`timeoutSeconds` 适用于每个 Attempt，因此不是跨重试的总实际耗时预算。
确认容器支持非 root 策略。请参阅
[执行模型](../concepts/execution-model.md#retries-and-deadlines)。

挂起会阻止计划和手动启动。独立的源执行控制要求 `job:ManageExecution`：
调度暂停阻止新的自动触发；执行暂停还会冻结新运行和尚未开始的派发。可能已启动
的执行继续保留观察和取消能力。暂停来源不会停止这些执行。身份删除是独立且
不可逆的控制，仅在停用该来源身份时使用。

## 恢复无响应的保存

保留草稿、目标、请求 UUID、摘要和原始 UID/resourceVersion。使用 Console 的
核对操作读取保留的操作结果。不要根据后来偶然相同但无关的定义推断请求已被接受。
再次写入前必须调查未知结果。持久化操作历史按操作者和目标限定范围；请求引用
不授予访问权限。

来源控制写入使用比较并设置版本。控制写入响应丢失后，先读取当前控制，再决定
是否再次写入。当前状态相同并不是独立的历史操作回执。

403 需要访问权限决策；重新检查或更换凭据不能安全解决预期权限问题。
409 需要读取当前状态并审核。即使 Console 仍可访问，Kubernetes API 不可用
也可能阻止检查、保存或就绪。

从旧 schema 升级的安装实例，必须先应用迁移 0028，才能检查 `namespace/name`
长度超过 64 个字符的定义。当前 schema 保留完整标识符。请参阅
[数据库迁移流程](../database-setup.md#migration-execution-and-compatibility)。
