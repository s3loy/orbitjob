# 已知问题与验证缺口

本页记录实现缺口和运行约束。[项目状态](status.md)介绍已实现能力；[验证记录](verification.md)记录经过测试的行为和适用性验证限制。

## 当前实现缺口

### 故障适用性验证需要完整的已安装恢复证据

负载工具分别为 Operator、Admin API、PostgreSQL 和 Scheduler 故障准备恢复金丝雀。验证交叉检查租户范围台账事实、Kubernetes 所有权、连续的测试夹具观测日志（journal）和 Scheduler 预算求值。副本就绪或人工提供恢复声明不能证明恢复。准备缺失、来源观测缺失或观测日志不连续时，结论仍为 `INCONCLUSIVE`。测试夹具在内存中保存观测日志；即使后续副作用可用，重启也会使当前运行的连续性失效。

这些检查需要针对实际候选版本运行已安装故障场景，才能用于适用性验证。它们不能证明任意网络分区或 Lease 丢失后的恢复。参见[负载测试](loadtest-guide.md)和限定范围的[验证记录](verification.md)。

### 全新机器接入仍未经验证

快速开始没有经过测量的全新机器完成时间保证。安装时长取决于下载、镜像构建和主机资源。安装检查参见[验证记录](verification.md)，接入范围参见[产品需求](prd.md)。

### 执行证据可能始终无法恢复

已绑定 Job 缺失时会转为非终态 ExecutionUnknown。空 Pod 清单、节点丢失和强制删除都不能证明物理进程终止。Unknown 和 CancelUnknown 继续占用 Forbid 并发槽，并排除在正常历史清理之外。没有强制释放 API；长期不确定可能需要手动隔离和单独审查的恢复流程。

新工作负载 Pod 会保留容器退出证据，直到 Operator 提交证据。因此 Operator 或数据库中断可能使已退出 Pod 及其 Job 继续存在。移除安装前，应恢复兼容 Operator 和数据库，并遵循[升级检查](operations/upgrading.md)。没有这类保护的历史工作负载不会在升级时获得缺失证据。

即使 Kubernetes 报告 Job 失败，没有可信容器退出状态的终态 Pod 仍保持未知。这包括在清理期间被标为 Failed、但从未调度的 Pod。其证据保留持续生效，直到单独审查的恢复确定可以安全移除的内容。

### 调度遵从性没有专用 SLI 派生

台账记录 `scheduled_for`，但支持的 SLI 类型和运行结果条件不会派生专用调度遵从性指标。已有状态和时长 SLI 不能完整衡量调度遵从性。词汇定义位于 `internal/core/domain/sli/create_input.go` 和 `criteria.go`；`scheduled_for` 本身不是遵从性求值。

### SLI 退役保留未解决历史

原始 Run 已删除、所有计划成员均有匹配事实，且计划和最新事实均超过最短 30 天重放期限后，Operator 才会按有界分页退役重放明细。可查询的 `unavailable` 事实会保留到支持的最长 SLO 窗口，当前为 8760 小时。事件时间缺失、投影不完整或 Run 被保留都会阻止自动退役。聚合快照和观测状态继续保留。

来源锁和事件运行锁串行化计划创建、事实记录和退役；已退役计划不能授权再次增加计数器。维护包含仍在 Operator 命名空间映射中的非活动来源和已暂停租户。将租户从该映射移除，也会将其从自动维护中移除。应保留其数据供显式审查。参见[结果恢复](database-setup.md#writer-cutover)。

## 运维与兼容性约束

- **较长定义身份需要迁移 0028。** 较旧模式将审计 `resource_id` 限制为 64 字符，可能在 checked save 时拒绝本身有效的 `namespace/name`。当前迁移扩展已有分区中的该列，不会截断审计身份。部署匹配应用前，应遵循[数据库迁移流程](database-setup.md#migration-execution-and-compatibility)。

- **账户发布需要已安装验收。** 个人账户候选版本包含迁移 0027、会话 origin 配置和带外设置与恢复工具。PostgreSQL 和浏览器测试夹具检查不能证明已安装环境升级成功。应保留原始 API key 和迁移输入通道，停止旧写入方，并在协调切换后验证人工会话、已有自动化和保留历史。
- **已有安装需要各自的维护验证。** 原生 kind 网络策略执行和有界采集器文件系统已在可丢弃集群中演练。安装自身的流量、挂载、容量和重启检查通过前，验证标志必须保持未设置。主机底层文件系统空间必须满足 40-GiB 前提条件。安排变更前应遵循[本地维护](local-maintenance.md)。

- **收敛检查观测的是已投影 JobRun 台账。** 托管运行器现在使用 `loadtest settle`，结合事务局部租户上下文和本次运行记录的修订版本 ID。观测缺失或查询错误仍属于未知。零计数不能证明未投影 CR 已完成，不会停止活动 cron 定义，也不能证明故障恢复；独立验证器仍负责最终判定。
- **历史投影切换。** 迁移 0012 保留旧聚合并确认已有终态行。它无法区分之前已计数的历史事件和遗漏的投影。自动恢复覆盖之后的终态转换；较早缺失投影需要离线审查。应用迁移前停止旧 Operator，之后启动新版本；新旧写入方重叠可能破坏去重。
- **迁移校验和通道不同。** 已有 Helm ConfigMap 的 `|-` 投影移除末尾 LF 字节；迁移器对实际输入计算哈希。因此对于已有台账，原始目录和 Helm 挂载 SQL 不是可互换的校验和通道。保留其原始输入通道，并同时保留源码清单和投影清单；绝不能重写已记录校验和。参见[数据库设置](database-setup.md#writer-cutover)。
- **凭据轮换需要协调。** 单独更改安装 Secret 不会改变 PostgreSQL 角色密码，也不会改变运行中 Pod 的环境。遵循[数据库设置](database-setup.md)中的 owner-init 和升级流程，验证新连接和重启后的工作负载。通过信任规则建立的回环或端口转发连接不能证明所提供密码有效。
- **集成测试需要可丢弃数据库。** 测试可能重建模式、准备角色并更改数据。专用 `TEST_DATABASE_DSN` 绝不能指向安装状态。支持的命令和串行化方式参见 [CONTRIBUTING.md](../CONTRIBUTING.md) 和 Makefile；没有强制的机器专属测试端口或容器名称。
- **命名空间接入必须显式完成。** 工作负载命名空间必须包含在 `operator.namespaceTenants` 中，并获得对应 RBAC。仅新增租户行不会准备命名空间或扩大 Operator 权限。
- **外部工作可能重复。** Job 退避和平台重试可能再次执行工作负载代码，重复产生外部副作用。需要时，工作负载必须通过幂等性确保重复副作用安全。工作也可能在应用代码执行前失败，因此重试不能保证业务副作用一定发生。成功触发响应确认的是运行资源，不代表工作负载已完成，也不代表台账行已对查询可见。

## 仍需现场证据

受控恢复场景不能证明任意网络分区恢复、生产韧性或通用 Job/Pod 垃圾回收时序。升级、回滚和备份恢复必须针对所涉及的实际源码、数据库历史和部署配置验证。已完成检查和待验证场景参见[验证记录](verification.md)。

负载配置持续时间和托管选项定义在 [test/load/config/](../test/load/config/) 和[负载工作流](../.github/workflows/loadtest.yml)中。读取 `result.json` 中的产品结论；仅负载工具执行成功不构成适用性验证。
