# 运行第一个作业

使用现有作业了解从请求到结果的流程。如果具有编写权限，第二部分将创建一个
小型容器作业并运行一次。示例假定安装实例已配置、Operator 处于活动状态，且
工作区命名空间已准备好执行。输出练习还要求已配置且具有可用容量的归档；
仅有日志权限不能预留空间。如果归档报告缺口或容量拒绝，应遵循
[日志状态指导](../tasks/read-logs.md)，并单独验证执行阶段。

## 开始前

获取安装实例的 Console 地址和有效工作区成员资格。运行现有作业要求在目标
工作区具有 `job:List`、`job:Get`、`job:Trigger`、`instance:List` 和
`instance:Get`，且不受资源组限制。需要输出时申请 `instance:ReadLogs`。
Operator 邀请预设包含这些操作；自定义策略和边界可以限制它们。Viewer 邀请不
允许触发。

创建作业还需获取 `job:Apply`、已授权命名空间，以及集群能够拉取并运行的镜像。
Kubernetes 命名空间映射、RBAC、存储和网络访问属于安装管理职责。仅创建工作区
不会提供这些条件。

登录并在 **Account → Open workspace** 中选择工作区。

## 运行现有作业

1. 打开 **Jobs**。搜索管理员提供的作业并打开。确认其命名空间、镜像、命令、
   超时和重试设置。
2. 选择 **Trigger**。挂起定义显示为 **Paused**，不能触发；应请作者审核并恢复。
3. 在对话框中确认请求。保留回执。初始阶段为空表示 Operator 尚未报告阶段。
4. 通过回执进入已记录运行，或使用作业的 **Runs** 标签页。接受请求和执行启动
   是独立事件。Forbid 下，手动请求可能因先前运行占用名额而等待，此时没有台账行。
5. 检查阶段和每个 Attempt。平台重试产生另一个 Attempt；Kubernetes 退避可以
   在同一个 Attempt 内创建多个 Pod。
6. 打开 **Execution logs**，读取保留的事件和输出。将输出用作证据前，检查任何
   缺口或采集警告。

请求已关联到记录的运行，且可以看到已确认结果时，本练习完成。观察请求被拒绝、
历史页为空或归档不可用，均不能确定执行失败。结果不确定时，保留回执并参阅
[触发与观察](../tasks/trigger-and-observe.md)。

## 作为作者创建作业

在已授权命名空间中使用一次性作业名称。以下工作负载打印一条消息并退出。确认
安装实例允许该镜像；受限镜像仓库或出站策略可能要求使用管理员提供的替代镜像。

| 设置 | 值 |
|---|---|
| 名称 | `hello-orbitjob` |
| 命名空间 | 管理员提供的执行命名空间 |
| 触发模式 | **Manual only** |
| 运行时 | **Shell**（`busybox:1.37.0`） |
| 执行方式 | **Shell script** |
| Shell 脚本 | `printf 'hello from OrbitJob\n'` |
| 超时 | 60 秒 |
| 平台尝试次数 | 1 |
| Kubernetes 退避限制 | 0 |

该镜像标签是示例，不是不可变摘要。需要可复现的镜像内容时，应固定已批准的摘要。
镜像必须支持执行策略的非 root 用户和安全设置。

1. 打开 **Jobs → Create a job**，输入上述设置。保留 Shell 运行时，将
   **Shell script** 中的 Hello 示例替换为上方脚本。附加参数保持为空。
2. 检查执行预览和资源请求及限制。本练习保持禁用重试。执行策略版本 1 下，
   启用重复执行要求显式声明重试安全。
3. 选择 **Review and save**，再选择 **Check against cluster**。该操作通过
   Kubernetes 准入校验已审核定义，不会保存。
4. 查看检查返回的配置，包括准入阶段所做的更改。选择 **Save definition** 并确认保存。
5. 等待 **Saved version is ready**。保存回执确认定义写入，就绪确认对应
   投影修订版本。如果检查暂停，选择 **Check readiness again**。如果已有更新
   版本处于活动状态，打开作业并审核该版本，再运行。
6. 选择 **Run once**，再选择 **Confirm run**，然后按第一部分跟踪回执。
   具有日志权限时，在 **Execution logs** 中找到 `hello from OrbitJob`，
   并单独确认运行的最终阶段。

仅手动作业具有空调度，并继续接受未来手动请求。保存不会启动作业。保存响应
丢失时，提交另一个定义前，先使用保留草稿的核对操作。如果命名空间、准入检查、
镜像拉取或运行时失败，保留报告的错误，并请安装实例管理员检查相关边界。
正常编写和恢复流程请参阅[管理作业](../tasks/manage-jobs.md)。

## 完成练习

停用测试工作负载前，确认执行已达到终态结果。仅手动定义不会启动自动工作，
可以保留以用于其他练习。不再需要时，请命名空间管理员按安装实例批准的原生
资源流程移除演示定义。移除定义、取消活动执行及已授权日志清理是独立操作。
应保留不确定的执行及其回执以供调查。
