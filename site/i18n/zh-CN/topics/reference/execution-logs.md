# 执行日志

执行归档跨 Attempt 保留有界的生命周期事件和容器 stdout/stderr，不依赖 Pod 保留。Console 的 **Execution logs** 面板提供 Attempt 和阶段筛选、搜索、跟随、复制和下载功能。[读取日志](tasks/read-logs.md) 介绍工作负载用户的操作流程。本页介绍安装容量、采集和恢复。

命令证据记录经过审查的镜像和 argv、已输出内容，以及观测到的退出码或信号。仅当工作负载打印或跟踪容器内执行的 shell 命令时，这些命令才会出现在日志中。应将保留输出视为敏感信息。日志可用性与 Run 已确认的业务结果是不同事项。

## 安装与容量

Chart 启用一个 Fluent Bit 节点采集器和一个 `orbitjob-log-archive` StatefulSet。归档在绑定来源前会验证 JobRun、Job 和 Pod UID，以及台账中固定的 Attempt。它将 gzip 分段、有界清单和生命周期事件写入专用 PVC。PostgreSQL 保存租户范围内的身份目录和清理请求。

归档使用受信任的 Runtime 数据库登录账户。Admin 使用独立的 Admin 登录账户读取目录和提交带审计的清理请求，并使用内部读取方 mTLS。采集器身份与读取方身份具有不同的内部能力。采集器镜像在 Chart values 中固定为 Fluent Bit 4.2.3 和一个摘要。

源码开发 kind 安装及所需工具和资源参见[本地部署](local-deployment.md)。数据库 PVC 迁移需要针对该安装单独制定方案；归档容量设置不能替代该流程。修改需要保留的数据库、归档或采集器存储前，遵循[备份与恢复](operations/backup-and-recovery.md)要求。默认归档 PVC 为 10 GiB。安装前应审查 `logs` 值；主机磁盘变大不会自动增加文件系统容量。

| 预算 | 默认值与行为 |
|---|---|
| 逻辑执行输出 | 32 MiB 未压缩数据，由各 Attempt、Pod、重启和流共享 |
| 超限执行窗口 | 最初 8 MiB 和最近 24 MiB；显示省略范围 |
| Workflow 输出 | 所有子执行合计 128 MiB；每个子执行仍有自身上限 |
| 租户输出 | 保留 2 GiB 未压缩输出 |
| 安装分配 | 在声明为 10-GiB 的 PVC 中计入 7 GiB 文件系统分配，另留可用空间储备 |
| 生命周期事件 | 1,024 个事件和 64 KiB 事件文本；超出部分记录为证据缺口 |
| 清单 | 256 KiB；有界的来源与重放元数据可能拒绝进一步准入 |
| 目录准入 | 128-MiB 逻辑身份预算和 256-MiB 物理表、索引与 TOAST 防护限制 |

卷准入使用配置限制、实际 PVC 申请量和文件系统剩余空间。受管写入会预留空间，但其他进程或底层设备故障仍可能耗尽存储。应监测归档用量、采集器健康状态和数据库大小。容量拒绝不会停止任务；其采集输出可能变为部分可用或不可用。

对于报告有限 inode 总数的文件系统，还必须保留超过 64 个可用 inode。inode 总数为零表示该计数不可用；准入仍会检查可用字节、配置分配量和可用空间储备。文件系统统计调用失败时会拒绝准入。即使容量检查成功，实际写入失败仍会被报告。

## 采集器状态与节点容量

默认采集器在每个节点的 `/var/lib/orbitjob-collectors/<namespace>/<release>` 下保存 tail 数据库和文件系统队列。命名空间与发行版名称用于隔离安装路径。在同一节点替换 Pod 会保留该目录；节点被替换或丢失时则不会保留。正常升级必须保留节点目录。

`logs.collectorBuffer` 限制 Fluent Bit 输出队列，默认值为 128 MiB。它不会对目录、SQLite 数据库或其他节点文件施加物理配额。选择生产采集器配置前，应在每个执行节点上配置并监测目录配额。为默认队列配置 256-MiB 配额后，声明如下：

```yaml
logs:
  collectorPersistence:
    mode: hostPath
    profile: production
    hostPathBase: /var/lib/orbitjob-collectors
    quotaVerified: true
    quotaBytes: 268435456
```

`quotaVerified` 是管理员声明。Helm 不会创建配额，也不会独立测量配额。生产渲染要求使用 hostPath、提供该声明，并配置至少为队列大小加 64 MiB 元数据余量的配额。开发渲染会在说明和注解中报告配额未经验证。显式设置 `mode: ephemeral` 会为可丢弃开发环境使用有界 `emptyDir` 存储，并在替换 Pod 时丢失偏移量和未导出的数据块。

每个来源文件有独立的标签和数据块路由，以限制永久无效来源批次对其他文件的影响。队列溢出可能丢弃旧数据块。超大物理行会被跳过，使后续行可以继续处理；应检查采集器警告和丢弃记录指标。节点丢失、队列驱逐、采集前轮转和本地存储故障都可能造成输出丢失。无法确定丢失范围时，覆盖情况会明确保持为未经验证。

## 摄取与重放

归档提交与 PostgreSQL 提交相互独立。摄取首先验证整个 JSON-lines 批次及其结构限制：8 MiB、20,000 条记录和 256 个来源文件。任何输出分组追加前，必须完成来源验证。JSON 格式错误或超出结构限制时返回 400/413，不会先接受一部分输出。验证可以独立于输出接受而注册来源元数据。

持久化失败可能发生在此前的输出分组已经提交之后。因此，收到 503 后必须重放原始来源记录。已持久化的每条记录来源指纹可对完整或重新分组的重放去重；采集器生成的请求 ID 不能作为重放依据。重放元数据本身也有界；耗尽后会拒绝新输出，并在可能时保留丢失标记。

成功的摄取响应报告 `received` 和 `rejected`，但不保证每条提交记录都已保留。永久无效来源，以及因容量、过期或隔离导致的拒绝，会分别计数。已知身份可以获得持久丢失标记；无法归属的来源失败只会计数，不会虚构执行身份。瞬时中断期间，采集器队列仍保持有界。调查采集丢失时，应同时检查归档和采集器证据。

## 保留与证据缺失

终态归档的保护期为完成时间和采集封存时间中较晚者起算的 15 天。较晚接受的输出会将保护期再延长 15 天，且不会替换已封存输出。已达到上限的封存归档会拒绝迟到输出并记录缺口。自动清理不会驱逐其他执行受到保护的输出。运行中的任务达到上限时，可以轮转自身输出窗口。

保护到期后，输出会被回收，并额外保留 15 天的 `expired` 摘要。JobRun 删除后目录维护仍会继续。按数量清理执行记录时会遵守归档保护期。正常的终态 Job 清理需要归档已完成并带有保护元数据（已封存或部分完成）、经过五分钟更新延迟，且终止证据已确定。清理会保留台账摘要。单独删除 Pod 不会删除已经保留的归档。

归档保留、执行历史和 Function 调用历史具有不同生命周期。日志保护不等于 Function 历史 TTL。Function 日志路由还需要可用的父定义，以解析当前分组授权；仅保留文件无法在父定义不可用后保留该 URL。

封存后的归档仍可能存在采集缺口。能够确定边界时，归档会记录缺口的范围，否则会标明范围未知。主清单写满后，预留控制块会记录丢失标记，以及用于保留和清理的已确认完成与封存信息。即使输出缺失，仍以 Run 已确认的成功、失败或取消结果为准。归档只能返回已经采集的输出。

**Delete retained logs** 需要独立的 `instance:DeleteLogs` 或 `function:DeleteLogs` 权限。该操作提交带审计的清理请求，可以在保护期内删除终态归档。回执确认的是请求，不代表立即删除。清理会保留执行摘要。

## API 与权限

实例归档路由要求使用没有资源组限制的凭据：

```text
GET    /api/v1/instances/{run_id}/logs/archive
GET    /api/v1/instances/{run_id}/logs/archive/download
DELETE /api/v1/instances/{run_id}/logs/archive
```

读取和下载需要 `instance:ReadLogs`；删除需要 `instance:DeleteLogs`。这些授权独立于普通运行读取权限。Function 历史使用 `/api/v1/functions/{id}/runs/{history_uuid}/logs/archive`，导出时加上 `/download`。该路由依据持久化的 Function 父定义和分组，使用 `function:ReadLogs` 或 `function:DeleteLogs` 授权。租户隔离和显式 Deny 贯穿所有操作。浏览器调用方不提供 Pod 或命名空间定位信息。

查询支持 `after`、`limit`（最大 1,000）、正数 `attempt` 和 `search`（最多 256 字符）。默认分页上限为 500。跟随操作从最后一个游标继续，搜索仅针对保留证据。响应包含采集状态、缺口、输出字节数、保留字节数、限制字节数和保护到期时间。下载包含省略信息、采集状态变化和明确结束标记。即使初始响应头已成功返回，部分传输也不属于完整导出。

独立的 `/attempts/{attempt}/logs` 路由从保留的 Kubernetes 资源读取有界快照，期限为五秒，最多包含末尾 500 行和 65,536 字节。`attempt` 指台账 Attempt 编号。该路由会验证不可变所有权，不承诺持久保留；Kubernetes 垃圾回收可能使其不可用。

归档读取传递调用方取消信号，并具有包含排队时间在内的五秒工作预算。每个归档进程允许四个并发读取，每租户最多两个。分段快照会与追加和删除协调，解压与搜索避免持有安装元数据锁。取消或预算耗尽时返回不可用，不会返回看似完整的空页面。Go 取消无法强制中断已经在操作系统中阻塞的文件系统调用。

## 完整性与恢复

分段缺失或损坏时返回部分页面，并携带省略序列范围；其余经过验证的分段仍可读取。清单缺失、格式错误、过大或校验和无效时，会隔离其以哈希命名的目录，保留文件和已计入的分配量，并拒绝在这些证据之上重新注册。健康归档仍保持可用。符号链接、不安全的根目录布局，或目录与清单身份不一致，都会阻止打开不受信任的根目录。

新清单包含内容校验和。没有校验和的旧清单继续执行结构和 gzip 完整性检查，不追溯保证内容校验和。校验和可检测损坏，但不能认证控制该卷的管理员所做的编辑。隔离目录不参与自动清理无引用文件，并继续占用容量。

检查 `orbitjob_archive_corruption_total` 并保留受影响目录。不要删除证据或构造空清单来清除错误。替换前应在隔离环境中验证协调备份。在匹配的源码检出中使用 Go 1.27.4 或更高版本，检查已停止的归档或一致的隔离卷副本：

```sh
go run ./internal/logarchive/inspectcmd --directory /path/to/archive-copy --timeout 1m
```

命令输出包含归档哈希和完整性检查结果的 JSON，不包含容器输出。底层程序未发现问题时退出 0，发现问题时退出 1，根目录不安全或检查不完整时退出 2。`go run` 还会报告非零的子进程退出状态。检查会拒绝活动写入锁，不会创建缺失的锁文件，并在达到 10,000 个归档目录或指定时间预算时停止。中断的检查不能证明剩余归档的完整性。副本本身必须一致。

## 归档运维与备份

在安装命名空间中检查归档 StatefulSet、采集器 DaemonSet、就绪探针和 `/metrics` 端点。指标使用有界标签，不包含输出文本或凭据。采集器的节点日志访问属于受信任的安装能力；工作负载和浏览器凭据不会获得节点、Secret 或 exec 权限。输出以不执行其内容的文本形式提供，仍属于敏感信息。

达到 PostgreSQL 物理元数据防护限制时，已有归档仍可更新状态并接受清理，但新注册会被拒绝。回收符合条件的行后，应由数据库所有者在维护窗口中执行 `VACUUM FULL execution_log_archives` 和 `ANALYZE execution_log_archives` 回收关系膨胀，再预期准入恢复。`VACUUM FULL` 需要排他锁和足够的临时存储；应按数据库维护安排执行。

将 PostgreSQL、归档卷和安装配置作为一个可恢复安装一并备份。在隔离环境中一并验证恢复后的目录身份、权限和文件。仅恢复数据库不会恢复输出；仅恢复归档不会恢复经过授权的查找。

应用回滚必须保留归档文件、增量模式和保留限制。停止采集不构成删除受保护归档或允许队列无限增长的依据。不可用输出不保证能够重建。[验证记录](verification.md) 记录文件系统、保留、PostgreSQL 授权和重启恢复证据的范围。这些结果不能用于认定另一安装合格，也不能证明采集没有缺口。
