# 安全策略

OrbitJob 的 Console 使用个人账户会话，自动化使用命名 API key。工作区成员
资格、操作和资源策略、PostgreSQL 角色与 RLS，以及 Kubernetes 命名空间控制
分别提供独立的授权边界。本策略描述当前源码；运行已发布版本时，应使用对应标签
中的策略。

## 报告漏洞

请通过 <justs3loy@gmail.com> 私下报告漏洞，邮件主题为 `[OrbitJob Security]`。
不要在公开 Issue、Discussion 或拉取请求中披露可用的利用方法或敏感安装数据。

报告应包含受影响的版本或提交、所需权限、最小复现、被跨越的租户、数据库角色或
命名空间边界、观察到的影响，以及建议的修正方式。仅在已获授权的环境中测试。
排除真实密钥、密码、DSN、Secret 内容和生产输出。

维护者确认报告可复现后，协调修复和披露。项目没有固定响应时间 SLA，也不承诺
长期支持分支。安全更新通过 [CHANGELOG](CHANGELOG.md) 中对应的发布记录标识。
公开披露后会注明报告者，除非报告者要求匿名。

## API key 与授权

API key 以 `otj_` 开头。数据库存储 bcrypt 摘要；正常创建仅返回一次明文，后续
读取只提供元数据。没有任何授权的密钥可以通过认证，但所有受保护能力仍被拒绝。
未知、已撤销、已过期或租户非活动状态的凭据收到相同的认证失败响应。认证或权限
存储故障则可能返回 503，不能据此认定凭据无效。

为每个调用方使用专用命名密钥，仅授予所需操作和资源。普通客户端和工作负载不得
使用引导凭据。撤销操作根据目标密钥已持久化的所有者和分组授权，并审计实际通过
认证的操作者。委派和边界传播不能扩大调用方的有效授权。显式 Deny 优先于 Allow；
不受支持或无法证明的包含关系会拒绝放行。

经过认证的身份自省返回凭据元数据和精确策略判定，不返回凭据、策略文档，也不
探测资源是否存在。

租户编写的策略使用已知的精确操作，以及受支持的完整路径段资源通配符。
通配操作能力由平台预设管理。每个受保护路由声明自身操作和目标。可信的租户、
分组、操作者和路径身份来自服务端及认证上下文，客户端绑定不能替换它们。
平台请求选择一个已授权租户，同时用于策略和数据范围。普通租户凭据不能选择
其他业务租户。

支持分组的读取和修改会解析已持久化的父分组。没有受支持分组限制的路由会拒绝
绑定分组的调用方。API key、策略、资源组、定义编写、触发、普通历史和日志
分别需要独立授权。资源 ID 或请求引用不授予访问权限。
[管理访问权限](docs/tasks/manage-access.md)列出了任务前提。

已提交密钥但交付失败后，Bootstrap 可以重试交付已配置的明文密钥。它校验现有
摘要，拒绝存在冲突的文件或 Secret 内容；它不能从数据库恢复明文，也不会静默
轮换密钥。其 Role 允许在命名空间内创建 Secret，并仅允许按名称获取
`bootstrap-api-key`，不允许 list/update/patch。已弃用的 `bootstrap.secretName`
值不会改变这一固定目标。

## 浏览器 Console

用户通过一次性安装能力令牌或工作区邀请获取个人账户。API key 不标识账户所有者，
也不能用于登录 Console。初始设置需要使用 `/orbitjob-identity` 及安装实例的
Admin DSN。持久化的已认领标记防止设置自动重新开放；丢失安装管理权限时，需要
由运维人员签发恢复能力令牌。请参阅[账户与恢复](docs/accounts.md)。

密码使用 Argon2id，内存为 64 MiB、迭代三次、并行度为一。密码至少需要 15 个
字符，最多为 1,024 个 UTF-8 字节，并通过本地常见密码阻止列表和短重复模式
检查。当前源码不提供邮件重置服务、OIDC、通行密钥或多因素认证。现有账户接受
邀请时必须使用该账户的有效会话，且不会修改密码。只有安装实例管理员可以签发
全局重置链接。密码更改或重置会撤销该账户的所有会话。

生产 cookie 使用 `__Host-orbitjob_session`、`HttpOnly`、`Secure`、
`SameSite=Strict`、`Path=/`，且不设置 `Domain`。PostgreSQL 仅存储会话
秘密值的哈希。记住登录的会话具有七天的绝对有效期；未勾选记住登录时，创建浏览器
会话 cookie，服务端有效期为八小时。轮询不会延长有效期。浏览器恢复可能保留
会话 cookie；使用共享设备的用户必须退出登录。

独立的 CSRF 令牌保存在页面内存中。通过 cookie 认证的写入要求精确匹配允许的
Origin，并携带 `X-CSRF-Token`；登录和能力令牌提交同样校验 Origin。显式无效的
Bearer 认证不会回退到会话 cookie。`CONSOLE_PUBLIC_ORIGIN` 可以固定精确
HTTPS 源地址；否则 Admin 要求 HTTPS 加请求 Host。反向代理必须保留公开 Host。
转发请求头不会放宽这一边界。

`CONSOLE_ALLOW_INSECURE_LOCALHOST=false` 为默认值。显式本地模式只允许
HTTP 回环地址，并使用不带 Secure 的 `orbitjob_session_local`。该模式不允许
通过节点或公开 HTTP 地址登录。请参阅
[源地址配置](docs/accounts.md#https-and-local-development)。

Console 静态资源和导航公开可用。`/healthz`、`/openapi.json` 和 `/metrics`
也无需认证；应在安装实例的网络或网关处控制它们的外部暴露。受保护 API 路由继续
执行认证、策略、请求体限制、速率限制和请求关联。缺失的静态资源和未知 API 路径
不会回退到浏览器应用。Console 响应设置同源 CSP、nosniff、禁止嵌入框架和
no-referrer。脚本、字体和样式均来自本地；组件库允许内联样式。安装包不包含
演示客户端。仅在可信的安装实例源地址输入凭据。同源脚本执行可以通过 HttpOnly
会话执行操作，因此仍需要 HTTPS、CSP 和设备保护。

每个工作区请求都会检查活动账户、成员资格和有效授权。安装实例管理员管理
全局账户和工作区元数据，不隐含工作负载访问权限。工作区创建者获得显式
所有者成员资格。禁用账户会撤销会话；禁用成员资格和更改角色会影响后续工作区
请求。特权账户变更，以及浏览器中的 API key、策略和分组写入，要求在 15 分钟内
完成过密码确认。用户操作者 ID 与密钥 ID 保持独立。

浏览器在 `sessionStorage` 中存储不含秘密的已选工作区 ID 和未确认的源控制意图。
保留的源控制意图按已认证主体、工作区和源隔离，同一主体可以在重新连接后审核。
退出登录、收到 401 或身份或工作区改变时，受保护的内存查询和操作状态会清除。
设置、邀请和重置片段会从地址栏移除，并保存在页面内存中。
一次性密钥结果使用独立于查询和
修改缓存的易失存储；丢弃或断开连接会移除它们，断开的客户端会丢弃延迟到达的
创建响应。创建结果丢失后需要进行核对，不会自动创建替代密钥。

Console 的 Job、Workflow 和 Function 编写草稿仅保存在当前连接的页面内存中。
重新加载、退出登录、收到 401 或更改身份或工作区会清除草稿。当前不提供服务端
私有草稿持久化和恢复功能。结束或更改连接前，应将未完成内容保存在 Console 之外。

已接受的定义保存和 Function 创建操作在服务端保留操作者及请求身份，以供核对。
其操作回执标识已接受的写入，不能恢复尚未保存的编写草稿。仅凭请求 UUID
不能获得操作访问权限。

## 定义、发现与监控证据

在线编写接受映射租户命名空间中的类型化 ScheduledJob/WorkflowJob spec，并独立
要求 Apply 权限。检查和持久化都需要授权。Kubernetes 预演检查已审核的载荷；
持久化要求提供其摘要、稳定请求身份以及预期 UID/resourceVersion。并发替换
会产生冲突。结果未知的写入保留身份，并根据操作历史协调，不会自动重新写入。
API 不提供任意 Kubernetes 元数据或资源写入。

默认 chart 为映射命名空间中的 Job/Workflow 定义启用验证 Webhook；调用失败时拒绝请求。
它校验最终类型化 spec、已审核摘要和当前服务端操作。显式配置的原生写入方免于
检查后保存回执要求，但仍需通过类型化 spec 校验。原生写入方配置属于安装管理
权限。webhook 不可用可能阻止定义持久化；禁用 webhook 会移除该最终对象检查。

Function Create/Update 操作独立于读取和调用。创建绑定租户、操作者、请求键和
规范化载荷。更新以原子方式比较已审核的定义版本；固定版本的调用会拒绝尚未就绪
或已经变化的版本。定义变更和审计一起提交。预设迁移仅扩展其指定的预设；自定义
策略不会隐式获得新操作。

Bearer 工作区目录仅返回已授权的名称、slug、状态和不可变 ID。租户密钥可以
查看自身标签；外部行要求有效的 `tenant:Get`，绑定分组的凭据不能发现其他工作区。
平台凭据没有隐式的自身行。可见性在分页前纳入显式 Deny 和递归边界。
目录返回可见结果的 `has_more`，不提供全局总数。仅供 Admin 使用的元数据读取方
不扩大普通租户表 RLS，也不授予工作负载权限。个人会话单独列出有效成员资格；
元数据发现从不创建成员资格。

### 监控证据

CheckRun、SLO 预算与历史以及告警读取会根据其实际父 Check 或 SLO 的分组和 ID
授权，也包括未绑定分组凭据适用的分组专属 Deny。其他分组的父资源表现为不可用。
CheckRun 和告警集合权限必须覆盖整个请求查询域。相关的逐 ID 或分组 Deny、
边界限制，或包含关系证明的计算预算耗尽，都会在读取项目或计数前拒绝请求；分页不能绕过
这些限制。成功的集合响应不会静默省略被拒绝的行或计数。

每种派生读取都需要自身操作。分组密钥的 SLO 响应省略内嵌 `current_budget`；
未绑定分组的访问仍要求对实际父分组和 ID 具备 `slo:GetBudget`。SLO 创建在写入
事务中校验同租户内有效的 SLI；对于限定范围的调用方，还要求 SLI 属于同一分组。
缺失或不可访问的引用返回未找到。

## PostgreSQL 角色与 RLS

| 角色 | 用途 |
|---|---|
| `orbitjob_table_owner` | schema 对象及已审核安全函数的 NOLOGIN 所有者 |
| `orbitjob_migrator` | 允许切换为表所有者的迁移登录身份 |
| `orbitjob_admin` | 管理写入、已审核账户安全调用和只读执行历史 |
| `orbitjob_runtime` | Operator、Scheduler、准入和归档使用的登录身份，具有所需运行时写入权限 |
| `orbitjob_operator` | NOLOGIN 执行授权角色；不是独立部署的登录身份 |

运行时进程不得使用安装所有者、表所有者或超级用户凭据。Operator 优先解析
`OPERATOR_DSN`，随后才使用 Runtime 回退。使用安装实例已配置的 Secret 名称、
键及迁移输入通道；请参阅[数据库设置](docs/database-setup.md)。

应用角色不拥有租户表。启用 ENABLE RLS，但不启用 FORCE RLS；NOLOGIN
所有者仍是维护边界。仓储在与查询相同的事务内设置事务局部 `app.tenant_id`。
连接池中使用会话级租户设置不安全。审计父表和直接分区按需授予追加及读取权限，
不授予应用 UPDATE、DELETE 或 TRUNCATE。领域修改与其审计以原子方式提交。

范围受限的 SECURITY DEFINER 操作覆盖普通租户限定之前的认证、引导、活动租户
枚举、密钥所有者发现、平台预设、工作区元数据及账户操作。它们固定 search_path、
撤销 PUBLIC 执行权限，并向指定角色授权。基线还会撤销 schema public 上的
PUBLIC CREATE。新增跨租户操作需要同等审核，以及真实 PostgreSQL 边界测试。

终态投影确认发生在幂等派生结果成功之后。SLI 增量与去重事实一起提交，保留期
长于普通运行清理周期。迁移 0012 保留旧聚合，不重放旧终态行；切换前必须停止
旧 Operator。已发布迁移的字节不可修改，包括注释。请参阅
[迁移流程](docs/database-setup.md#migration-execution-and-compatibility)。

## Kubernetes 工作负载与执行恢复

命名空间映射决定租户身份；工作负载自身声明的租户不决定该身份。Admin 具有
命名空间内定义 get/create/patch、运行 create/get/patch、Job get、Pod get/list
和 pods/log get 权限。它没有 Job/Pod 生命周期写入、状态写入、Secret、exec
或 attach 权限。Operator 仅在映射命名空间中管理执行、状态和保留操作；其
Lease 权限位于安装命名空间。JobRun 操作者归因信任资源写入方：允许写入 JobRun
CR 的主体可以选择其 actor 字段。应将直接 CR 写入限制在预期的控制平面身份。

工作负载 Pod 禁用服务账户令牌挂载，并使用 `restartPolicy: Never`。执行策略
版本 1 增加非 root UID 65532、RuntimeDefault seccomp、禁止权限提升和移除
capabilities，并固定 CPU、内存和临时存储请求及限制。镜像必须能够在这些设置下
运行。旧版 0 不会仅因升级 Operator 就获得全部版本 1 保护。不得为了补偿不受
支持的应用要求而扩大默认工作负载 ServiceAccount 的权限。

容器仍执行工作负载提供的代码。应根据安装实例的信任模型应用命名空间准入、
Pod Security、已批准镜像和网络控制。chart 的 restricted-v1 NetworkPolicy
选择版本 1 工作负载 Pod，拒绝入站流量，并将出站流量限制为已配置 DNS 和允许的
目标。网络策略是否生效取决于 CNI。生产渲染要求管理员声明已成功验证策略生效；
Helm 渲染不能验证数据包被拒绝。选择器外的旧 Pod 需要独立网络策略。HTTP 探测也会从其
工作负载命名空间发出外部请求，应相应配置允许的目标。

接管 Run/Attempt 要求完整身份和不可变 Job UID。取消补丁和保留删除使用身份及
版本前置条件。Workflow 停止会阻止创建新子运行。当前名称保留完整触发摘要；
匹配的历史名称仅作为兼容性查找候选。保留过程在删除终态资源并清理记录前，
校验原始租户、来源、修订版本和触发身份。

已绑定 Job 缺失会产生非终态 `ExecutionUnknown`，保留并发名额，并阻止自动
替换。完整停止证据可用之前，取消可能保持 `CancelUnknown`。空 Pod 列表、
删除时间戳、节点丢失或外部强制移除均不能证明工作负载代码已经停止。平台没有
公开的强制裁定 API。

新工作负载 Pod 通过 Operator 管理的 finalizer 保留终止证据。Operator 先
持久化完整的所属容器证据，再通过 Pod UID/resourceVersion 检查释放其 finalizer。
取消还要求控制器确认停止，随后持久化证明并释放证据 finalizer，之后才删除原始 Job。
Admin 和采集器没有 Pod patch 权限。这会在故障期间保留可用观测，但在证据
丢失后不能证明终止。Client-go 领导者机制协调单实例工作；事务化源准入提供独立
的并发边界。请参阅
[执行恢复](docs/architecture.md#execution-recovery-and-concurrent-admission)。

即使使用 Never 重启策略，Kubernetes 退避和平台 Attempt 仍可能重复产生外部
效果。版本 1 在启用重复执行前要求 retrySafe。请求幂等性不能保证这些外部效果
恰好发生一次。

## 执行日志与安装秘密

日志读取使用独立的父资源专属 ReadLogs 授权，以及已记录的不可变 JobRun、Job
和 Pod 归属。实例路由拒绝限定分组范围的凭据；Function 路由解析实际父分组和
历史 UUID。旧快照路由限制字节数、行数和时间，不承诺持久化保留。Kubernetes
垃圾回收可能移除该来源证据。

可信 Fluent Bit 采集器读取映射的任务 CRI 路径，并通过采集器 mTLS 将输出转发到归档；
Admin 使用读取方 mTLS。单一归档写入方使用 Runtime 数据库凭据和专用有界 PVC。游标读取、
跟随、搜索、导出及经过审计的 DeleteLogs 请求继续独立授权。输出按不可执行的
文本处理，可能包含秘密。容量或采集故障会产生缺口；封存归档不能证明覆盖完整。
保留、完整性和恢复行为请参阅[执行日志](docs/execution-logs.md)。

生成的安装状态、密钥、密码、DSN、Secret 明文和敏感冒烟输出不得进入版本控制
或公开报告。保护 `.runtime/`、`.kind/`、本地凭据文件、备份和管理员设备。
使用严格的文件权限和经过批准的秘密交付流程。不要将密钥放入 URL、前端构建
变量或公开文档站点输入。数据库、归档卷和安装配置应一起备份，并在隔离环境中
演练恢复。

记录的验证仅适用于其来源和环境，不能证明任意部署的安全性或故障恢复能力。
当前证据和限制记录在[验证记录](docs/verification.md)及
[已知问题](docs/known-issues.md)中。
